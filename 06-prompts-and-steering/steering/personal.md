# My personal working rules

These rules apply in every project. Save this file as
`~/.kiro/steering/personal.md` and change it to describe you.

## How to answer me

- Give the short answer first, then the details.
- Show one small example before the theory.
- When you change something, show it as "before" and "after".

## Code

- Handle errors on purpose, with a clear message. Never hide an error.
- Write comments that explain why, not what. The code shows what.
- When I ask for a new feature, write the test first, then the code.

## Debugging

- Start debug log lines with `[DEBUG]` and the function name, so I can find
  them.
- Remove debug lines before you say the work is done.

## My tools

- Editor: VS Code
- Shell: zsh
- Formatter: Prettier, 100-character lines
- Tests: Jest
